# 全量更新使用指南

## 概述

本系统使用 `electron-updater` 进行全量更新，下载完整的安装包进行版本升级。

**特点：**
- 下载完整安装包，确保所有文件一致
- 更新时自动保留数据库和用户数据
- 支持自动检查更新

## 系统架构

全量更新系统由以下组件组成：

### 1. 更新服务器
- 静态文件服务器，托管安装包和 `latest.yml` 文件
- 支持断点续传

### 2. electron-updater
- Electron 官方更新库
- 自动检查、下载、安装更新

### 3. NSIS 安装器
- 自定义安装脚本
- 升级安装时自动保留数据库

## 使用步骤

### 步骤 1: 配置更新服务器

在应用中配置更新服务器地址：

1. 打开应用，进入 **设置** > **系统设置**
2. 在 **更新服务器地址** 输入框中填写服务器地址
3. 点击 **测试连接** 按钮验证连接
4. 点击 **保存** 按钮保存设置

**更新服务器地址格式：** `http://your-server:8080/updates/`

### 步骤 2: 部署更新包到服务器

将构建好的更新文件上传到服务器：

```
release/
├── latest.yml                          # 版本清单文件
├── 仓库管理系统 Setup x.x.x.exe       # 安装包
└── 仓库管理系统 Setup x.x.x.exe.blockmap  # 增量下载映射（可选）
```

**服务器目录结构：**
```
/updates/
├── latest.yml
├── 仓库管理系统 Setup 1.3.5.exe
└── 仓库管理系统 Setup 1.3.5.exe.blockmap
```

### 步骤 3: 检查和应用更新

#### 方式一：自动检查更新

应用会自动检查更新：
- 启动后 5 秒自动检查一次
- 之后每 4 小时自动检查一次

#### 方式二：手动检查更新

1. 进入 **设置** > **关于** 页面
2. 点击 **检查更新** 按钮

#### 应用更新

当发现新版本时：

1. 界面会显示新版本信息，包括：
   - 版本号
   - 发布日期
   - 更新包大小
   - 更新内容说明

2. 点击 **下载更新** 按钮开始下载

3. 下载完成后，点击 **立即安装** 按钮

4. 应用会自动退出并启动安装程序

5. 安装程序会：
   - 检测到已安装的旧版本
   - 自动保留数据库和用户数据
   - 覆盖安装新版本

6. 安装完成后，重新启动应用即可

## 更新流程详解

### 检查更新流程

```
客户端 -> 服务器: GET /updates/latest.yml
服务器 -> 客户端: 返回版本清单
客户端: 比较版本号，判断是否需要更新
```

`latest.yml` 文件内容示例：
```yaml
version: 1.3.5
files:
  - url: 仓库管理系统 Setup 1.3.5.exe
    sha512: xxxxx
    size: 101163689
path: 仓库管理系统 Setup 1.3.5.exe
sha512: xxxxx
releaseNotes: |-
  版本更新内容
releaseDate: '2026-05-11T01:02:29.777Z'
```

### 下载更新流程

```
客户端 -> 服务器: GET /updates/仓库管理系统 Setup 1.3.5.exe
服务器 -> 客户端: 流式传输安装包（支持断点续传）
```

下载过程中会：
- 实时显示下载进度
- 验证文件哈希确保完整性
- 支持断点续传

### 安装更新流程

```
1. 主应用退出
2. 启动安装程序
3. 检测已安装版本
4. 保留 data 目录（数据库）
5. 覆盖安装新版本
6. 安装完成
7. 用户启动应用
```

## 数据保留机制

### NSIS 安装器配置

安装器通过 `build/installer.nsh` 脚本实现数据保留：

1. **升级检测**：检查注册表判断是否是升级安装
2. **选择性删除**：升级时只删除程序文件，保留 `data` 目录
3. **自动迁移**：首次安装时自动从旧版本迁移数据

### 保留的文件

- `data/inventory.db` - 数据库文件
- `data/backups/` - 备份文件
- `logs/` - 日志文件

## 故障排除

### 1. 检查更新失败

**可能原因：**
- 更新服务器未启动
- 更新服务器地址配置错误
- 网络连接问题

**解决方法：**
1. 确认更新服务器已启动
2. 检查更新服务器地址是否正确
3. 测试网络连接
4. 查看应用日志

### 2. 下载更新失败

**可能原因：**
- 网络中断
- 磁盘空间不足
- 服务器文件不存在

**解决方法：**
1. 检查网络连接
2. 清理磁盘空间
3. 确认服务器文件存在
4. 重新尝试下载

### 3. 安装更新失败

**可能原因：**
- 安装程序被拦截
- 权限不足
- 文件被占用

**解决方法：**
1. 关闭杀毒软件
2. 以管理员身份运行
3. 关闭所有应用窗口
4. 手动运行安装程序

### 4. 更新后数据丢失

**可能原因：**
- 安装器配置错误
- 手动删除了 data 目录

**解决方法：**
1. 检查 `data/backups/` 目录是否有备份
2. 从备份恢复数据库
3. 重新安装旧版本

## 开发指南

### 生成 latest.yml

构建应用时会自动生成 `latest.yml` 文件：

```bash
npm run build
```

生成的文件在 `release/` 目录下。

### 自定义更新内容

在 `package.json` 中配置更新内容：

```json
{
  "build": {
    "releaseInfo": {
      "releaseNotes": "v1.3.5 更新内容\n\n✨ 新增功能：\n- 功能1\n- 功能2\n\n🐛 问题修复：\n- 修复问题1"
    }
  }
}
```

### 自定义安装器

修改 `build/installer.nsh` 文件来自定义安装行为：

- 修改 `customRemoveFiles` 宏：控制升级时删除哪些文件
- 修改 `customUnInstall` 宏：控制卸载时的行为
- 修改 `customInstall` 宏：控制安装后的操作

### 搭建更新服务器

可以使用任何静态文件服务器，例如：

**Nginx 配置示例：**
```nginx
server {
    listen 8080;
    server_name your-server.com;
    
    location /updates/ {
        alias /path/to/release/;
        autoindex on;
    }
}
```

**Node.js 服务器示例：**
```javascript
const express = require('express')
const app = express()

app.use('/updates', express.static('release'))

app.listen(8080)
```

## 配置选项

### electron-updater 配置

在 `package.json` 中配置：

```json
{
  "build": {
    "publish": {
      "provider": "generic",
      "url": "http://your-server:8080/updates/"
    }
  }
}
```

### NSIS 配置

```json
{
  "build": {
    "nsis": {
      "oneClick": false,
      "allowToChangeInstallationDirectory": true,
      "deleteAppDataOnUninstall": false,
      "include": "build/installer.nsh"
    }
  }
}
```

## 注意事项

1. **备份重要数据**：更新前建议备份数据库
2. **网络环境**：建议在稳定的网络环境下进行更新
3. **磁盘空间**：确保有足够的磁盘空间（至少 500MB）
4. **关闭应用**：更新前关闭所有应用窗口
5. **不要中断**：更新过程中不要强制关闭安装程序

## 常见问题

### Q: 更新后数据会丢失吗？

A: 不会。安装器会自动保留 `data` 目录中的数据库和备份文件。

### Q: 如何手动更新？

A: 下载最新版本的安装包，直接运行安装程序即可。安装器会自动检测旧版本并保留数据。

### Q: 更新失败后怎么办？

A: 可以手动下载安装包进行安装。如果数据丢失，可以从 `data/backups/` 目录恢复备份。

### Q: 如何回退到旧版本？

A: 下载旧版本的安装包，直接安装即可。数据库通常是向前兼容的。

### Q: 更新包有多大？

A: 更新包大小取决于应用的体积，通常在 100MB 左右。具体大小会在更新界面显示。
